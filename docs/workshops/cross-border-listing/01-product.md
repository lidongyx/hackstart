# 01 准备产品资料与事实边界

选一个单一产品，不要一开始做整个产品目录。先把资料整理成事实表：

| 字段 | 内容 |
| --- | --- |
| 产品名称 |  |
| 核心用途 |  |
| 材质 / 规格 |  |
| 可选配置 |  |
| 最小起订量 |  |
| 交付周期 |  |
| 包装方式 |  |
| 认证或测试 |  |
| 已确认卖点 |  |
| 不允许承诺的内容 |  |

把客户名称、真实报价、内部成本、供应商联系方式替换成示例值。没有证据的认证、库存、交期和性能不要让 Codex 自动补齐。

## 给 Codex 的资料检查任务

```text
请检查这份产品资料并分成三类：
1. 已确认事实：可以直接写入对外资料。
2. 需要销售或供应链确认：不能直接承诺。
3. 缺失信息：需要向客户或内部同事补问。

不要改写事实，不要自行补充认证、库存、价格、交期或性能数据。
最后给出一份“上架前必须确认”的清单。
```

## 通过标准

- 产品资料只覆盖一个产品和一个目标场景。
- 已确认事实与待确认信息分开。
- 你能列出至少 3 项不能直接对外承诺的内容。
