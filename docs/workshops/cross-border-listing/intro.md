# 用 Codex 做一份外贸产品上架包

这是一个面向外贸业务员、跨境电商运营和独立卖家的实战 Workshop。你会从一份脱敏产品资料出发，让 Codex 产出一套可以交给设计、销售和客服继续使用的上架材料。

## Workshop 参数

| 参数 | 内容 |
| --- | --- |
| 难度 | 入门，2 / 5 |
| 预计操作时间 | 90-120 分钟 |
| 最终成果 | 中英双语产品资料、3 类询盘回复和跟进表 |
| 需要准备 | 一个产品的规格、卖点、交付范围和常见问题 |
| 工具 | Codex、表格或文档编辑器 |

不要把 Workshop 变成“把中文翻成英文”。最终结果必须把事实、卖点、适用客户和下一步沟通分开，并标出不能确认的内容。

## 你要完成的事情

1. 整理产品事实和禁止虚构的边界。
2. 生成中英双语标题、简介、规格和 FAQ。
3. 生成首次回复、报价前澄清和跟进三类模板。
4. 用一个虚构询盘测试回复是否能推动下一步。
5. 提交一份可交接给运营或销售的上架包。

进入 [01 准备产品资料](#01-product) 开始。


<a id="01-product"></a>

## 01 准备产品资料与事实边界

选一个单一产品，不要一开始做整个产品目录。先把资料整理成事实表：

| 字段 | 内容 |
| --- | --- |
| 产品名称 |  |
| 核心用途 |  |
| 材质 / 规格 |  |
| 可选配置 |  |
| 最小起订量 |  |
| 交付周期 |  |
| 包装方式 |  |
| 认证或测试 |  |
| 已确认卖点 |  |
| 不允许承诺的内容 |  |

把客户名称、真实报价、内部成本、供应商联系方式替换成示例值。没有证据的认证、库存、交期和性能不要让 Codex 自动补齐。

### 给 Codex 的资料检查任务

```text
请检查这份产品资料并分成三类：
1. 已确认事实：可以直接写入对外资料。
2. 需要销售或供应链确认：不能直接承诺。
3. 缺失信息：需要向客户或内部同事补问。

不要改写事实，不要自行补充认证、库存、价格、交期或性能数据。
最后给出一份“上架前必须确认”的清单。
```

### 通过标准

- 产品资料只覆盖一个产品和一个目标场景。
- 已确认事实与待确认信息分开。
- 你能列出至少 3 项不能直接对外承诺的内容。


<a id="02-listing"></a>

## 02 生成双语上架资料

根据事实表生成一套结构一致的中英双语资料。英文不是逐字翻译练习，要保证规格、单位、数量和条件与中文事实一致。

### 推荐交付结构

```md
## 产品标题 / Product title

### 一句话简介 / One-line description

### 主要卖点 / Key benefits

### 规格 / Specifications

### 适用客户 / Suitable for

### 包装与交付 / Packaging and delivery

### 常见问题 / FAQ

### 待确认信息 / To be confirmed
```

### 给 Codex 的生成任务

```text
根据已经确认的产品事实，生成中英双语上架资料。

要求：
- 标题、规格、单位、数量和条件必须逐项对应。
- 只写已确认事实；待确认内容单独列出，不能伪装成卖点。
- 英文自然、简洁，适合采购人员快速阅读。
- 不使用绝对化承诺，例如“100%”“绝对无风险”“永久有效”，除非资料中有证据。
- FAQ 至少覆盖规格、定制、包装、交付和售后五个方向。
```

### 逐项核对

随机选择 10 个规格、数字或条件，对照事实表检查中英文两侧是否一致。发现不一致时，先修正资料源或提示词，再生成下一版。

### 通过标准

- 双语资料结构一致，读者不需要来回猜字段对应关系。
- 所有数字和条件都能追溯到事实表。
- FAQ 没有擅自承诺价格、库存、认证或交期。


<a id="03-inquiry"></a>

## 03 生成询盘回复与跟进表

准备一条虚构询盘，例如：

```text
We are looking for 500 units for a retail project. Please share lead time,
customization options, packaging details and your best quotation.
```

让 Codex 生成三种模板：首次回复、信息不完整时的澄清回复、已报价后的跟进回复。回复要推动下一步，但不能把未确认内容写成确定答案。

### 回复任务卡

```text
基于已确认的产品资料，生成三类英文邮件，并提供中文意图说明：
1. 首次询盘回复：确认需求、说明已知信息、提出下一步。
2. 澄清回复：列出报价前必须确认的 5 个问题。
3. 跟进回复：礼貌确认客户是否收到资料，并提供一个明确回复选项。

所有价格、交期、库存、认证和定制能力如果没有事实依据，必须写成待确认问题。
```

### 跟进表

| 客户代号 | 需求摘要 | 已确认信息 | 待补问题 | 下一步 | 截止时间 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| Buyer A | 500 units | 数量、用途 | 包装、交期 | 补充问题并确认报价范围 | 2026-09-xx | 待回复 |

### 通过标准

- 三类回复的场景和下一步动作不同。
- 回复没有虚构报价、库存、交期或认证。
- 跟进表可以交给另一个同事继续处理。


<a id="04-review"></a>

## 04 验收与提交打卡

最后请一位同事只看上架包，不看你的生成过程，回答三个问题：产品是什么、客户下一步要提供什么、哪些信息仍然不能承诺。如果回答不出来，优先改结构和字段，不要只加更多形容词。

### 验收清单

- [ ] 中文和英文的产品事实、数字和单位一致。
- [ ] 已确认、待确认和缺失信息有明确区分。
- [ ] FAQ 覆盖规格、定制、包装、交付和售后。
- [ ] 三类询盘回复都有明确下一步。
- [ ] 跟进表有状态、负责人或截止时间。
- [ ] 文档中没有真实客户身份、邮箱、电话、报价或内部供应商信息。

### 最终交付模板

```md
### 上架包
- 产品和目标客户：
- 双语资料：
- FAQ：

### 询盘跟进
- 我准备的三类回复：
- 必须先确认的五个问题：
- 跟进表字段：

### 复盘
- Codex 帮我节省的时间：
- 我人工核对的字段：
- 仍然不能自动化的判断：
```

提交脱敏后的上架资料截图、询盘回复摘要和跟进表截图。通过标准是销售或运营同事可以接着使用，而不是只得到一段看起来流畅的英文。
