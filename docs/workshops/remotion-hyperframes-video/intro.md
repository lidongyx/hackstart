# 用 Codex + Remotion + HyperFrames 生成短视频

这是一个面向视频剪辑、课程运营和内容团队新人的视频 Workshop。你会把一个主题拆成脚本、镜头和素材，再让 Codex 协调 Remotion 与 HyperFrames 完成一条 30-60 秒的短视频。

## Workshop 参数

| 参数 | 内容 |
| --- | --- |
| 难度 | 进阶，3 / 5 |
| 预计操作时间 | 120-180 分钟 |
| 最终成果 | 一条 MP4 视频、镜头表、可复用工程目录和验收记录 |
| 需要准备 | 一个办公技巧、产品功能或活动主题，3-8 个有权使用的素材 |
| 工具 | Codex、Remotion、HyperFrames、现有图片或音频素材 |

本 Workshop 不要求先学会所有视频软件。目标是跑通一条从主题到成片的可重复工作流：输入明确、时间线可读、渲染可重做、成片有人检查。

## 你要完成的事情

1. 写出 30-60 秒脚本和镜头表。
2. 用 Codex 建立 Remotion / HyperFrames 工程结构。
3. 完成画面、字幕、节奏和音频的第一版。
4. 渲染桌面端和手机端预览，检查可读性与节奏。
5. 提交成片、镜头表、工程截图和一次复盘。

进入 [01 脚本与素材](#01-script) 开始。


<a id="01-script"></a>

## 01 写脚本与镜头表

先把视频限制在一个结果上，例如“让观众在 45 秒内学会用 Codex 整理会议纪要”。不要把多个教程、品牌故事和产品介绍塞在同一条视频里。

### 镜头表模板

| 镜头 | 时长 | 画面 | 旁白 / 字幕 | 素材 | 目的 |
| --- | --- | --- | --- | --- | --- |
| 01 | 0-4s | 问题场景 | “资料很多，但没人知道下一步。” | 自制画面 | 建立问题 |
| 02 | 4-15s | 操作过程 | 关键步骤 | 截图或录屏 | 展示方法 |
| 03 | 15-35s | 结果对比 | 结果和注意事项 | 生成画面 | 证明有效 |
| 04 | 35-45s | 行动提示 | 下一步怎么做 | 品牌结尾 | 收束 |

### 给 Codex 的任务卡

```text
请把下面的主题拆成一条 30-60 秒短视频的镜头表。
要求：
- 每个镜头包含开始时间、结束时间、画面、字幕、素材和转场。
- 每个镜头只表达一个信息。
- 字幕要适合手机屏幕阅读，避免一屏塞太多字。
- 先标记需要我提供的素材，不要虚构素材已经存在。
- 最后给出旁白总字数和预计时长。
```

### 素材清单

把素材命名成可读的名字，例如：

```text
assets/
  screen-codex-task.png
  product-detail.jpg
  voiceover.wav
  logo.png
```

只使用你有权处理的图片、声音、字体和品牌元素。没有素材时，先用占位块，不要在工程里偷偷引用本机绝对路径。

### 通过标准

- 镜头表能在不看代码的情况下说明视频要讲什么。
- 总时长、字幕量和素材需求已经可估算。
- 每个素材都有来源或使用许可说明。


<a id="02-build"></a>

## 02 用 Codex 建立视频工程

让 Codex 先阅读镜头表和素材目录，再创建或修改工程。不要直接要求它“做一个很酷的视频”，而要让它按时间线和验收条件工作。

### 推荐交付结构

```text
video-workshop/
├── src/
│   ├── Composition.tsx
│   ├── scenes/
│   └── data.ts
├── public/assets/
├── design.md
└── package.json
```

实际目录以你的模板为准。核心要求是镜头数据、素材引用和组件结构可读，下一次改时不需要重新猜每个时间点的含义。

### 第二次任务卡

```text
请基于镜头表和当前素材目录，完成第一版视频工程。

要求：
- 使用 Remotion 组织可渲染的 Composition。
- 使用 HyperFrames 的时间线和动效约定表达镜头节奏。
- 将镜头时长、字幕和素材引用放在可读的数据结构中。
- 不修改原始素材，不写入 Token 或本机绝对路径。
- 先完成清晰、稳定的版本，再添加装饰性动效。
- 运行项目已有的检查或渲染命令，并报告失败原因。
```

### 第一版自检

- 时间线从头到尾可以播放，没有空白帧或突然跳回开头。
- 字幕不会被画面主体遮挡，手机尺寸下也能读清。
- 图片比例正确，没有拉伸；音频不会突然爆音。
- 工程不依赖你电脑上某个临时目录才能运行。

### 通过标准

- 能在本地预览完整视频。
- 至少有一个可重复修改的镜头数据入口。
- Codex 报告了运行命令和仍未解决的问题。


<a id="03-render"></a>

## 03 渲染、验收与提交打卡

先渲染低分辨率预览，再渲染最终文件。这样可以在发现字幕太小、节奏太慢或素材缺失时快速返工，不必每次都等待完整导出。

### 验收清单

- [ ] 桌面端和手机端预览都能看懂。
- [ ] 0-3 秒内说明了主题或问题。
- [ ] 字幕没有超出安全区域，关键文字没有被遮挡。
- [ ] 音频起止自然，旁白和背景音不会互相覆盖。
- [ ] 所有素材有来源，工程中没有 Token 或本机路径。
- [ ] 最终视频可以从工程重新渲染，而不是只剩一个孤立 MP4。
- [ ] 至少记录了一次返工，以及返工解决了什么问题。

### 最终交付模板

```md
### 视频
- 主题：
- 时长：
- 输出文件：
- 目标平台或画幅：

### 工程
- 预览 / 渲染命令：
- 镜头数量：
- 可复用的数据或组件：

### 验收
- 我检查的设备或画幅：
- 返工内容：
- 仍需人工处理的部分：
```

提交成片截图或封面、镜头表、工程结构截图和过程记录。不要在视频、终端截图或打卡文字中暴露 API Key、私人音频、客户资料或内部网址。

通过标准是别人可以理解视频、复查镜头，并在你的工程上继续修改，而不是只看到一个导出文件。
