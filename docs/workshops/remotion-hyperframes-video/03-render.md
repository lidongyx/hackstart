# 03 渲染、验收与提交打卡

先渲染低分辨率预览，再渲染最终文件。这样可以在发现字幕太小、节奏太慢或素材缺失时快速返工，不必每次都等待完整导出。

## 验收清单

- [ ] 桌面端和手机端预览都能看懂。
- [ ] 0-3 秒内说明了主题或问题。
- [ ] 字幕没有超出安全区域，关键文字没有被遮挡。
- [ ] 音频起止自然，旁白和背景音不会互相覆盖。
- [ ] 所有素材有来源，工程中没有 Token 或本机路径。
- [ ] 最终视频可以从工程重新渲染，而不是只剩一个孤立 MP4。
- [ ] 至少记录了一次返工，以及返工解决了什么问题。

## 最终交付模板

```md
## 视频
- 主题：
- 时长：
- 输出文件：
- 目标平台或画幅：

## 工程
- 预览 / 渲染命令：
- 镜头数量：
- 可复用的数据或组件：

## 验收
- 我检查的设备或画幅：
- 返工内容：
- 仍需人工处理的部分：
```

提交成片截图或封面、镜头表、工程结构截图和过程记录。不要在视频、终端截图或打卡文字中暴露 API Key、私人音频、客户资料或内部网址。

通过标准是别人可以理解视频、复查镜头，并在你的工程上继续修改，而不是只看到一个导出文件。
