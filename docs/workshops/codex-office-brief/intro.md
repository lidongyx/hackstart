# 用 Codex 把杂乱资料变成工作简报

这是一个面向办公和运营新人的入门 Workshop。你会把一组散落的会议记录、邮件片段、表格或产品资料交给 Codex，最后交付一份可以直接用于跟进工作的简报。

## Workshop 参数

| 参数 | 内容 |
| --- | --- |
| 难度 | 入门，1 / 5 |
| 预计操作时间 | 60-90 分钟 |
| 最终成果 | 一份工作简报、行动项表和待确认问题清单 |
| 需要准备 | 3-8 份已脱敏的工作资料，或一组自拟样例文件 |
| 工具 | Codex、文本文件或表格编辑器 |

这是一个任务，不是资料总结比赛。最终简报必须回答“接下来谁在什么时候做什么”，而不是只把原文换一种说法。

## 你要完成的事情

1. 让 Codex 先盘点文件和信息缺口，不要一上来就要求写总结。
2. 生成一页结构清楚的工作简报。
3. 把行动项、风险和待确认问题分开。
4. 人工抽查关键数字、日期、负责人和引用来源。
5. 提交一份能让同事接着执行的最终记录。

完成后进入 [01 准备输入](#01-input)，再依次完成资料盘点、简报生成和验收。


<a id="01-input"></a>

## 01 准备资料与安全边界

先准备一组可以公开练习的资料。可以选择已经脱敏的会议纪要、项目进度、产品说明、客户需求或一张小型表格，也可以用下面的样例主题自拟 3-8 份文件：

```text
项目背景.md
会议记录.md
客户反馈.csv
当前进度.md
```

把真实姓名替换为“客户 A”，把邮箱和电话替换为 `example.com` 示例值，把内部链接替换为“内部文档链接”。不要为了完成 Workshop 上传原始客户文件。

### 建立资料清单

给每份文件补一个最小说明：

| 文件 | 来源 | 时间 | 可能回答的问题 |
| --- | --- | --- | --- |
| 会议记录 | 周会 | 2026-09-xx | 做了哪些决定？ |
| 客户反馈 | 工单导出 | 2026-09-xx | 哪些问题重复出现？ |
| 当前进度 | 项目表 | 2026-09-xx | 哪些事项逾期？ |

### 第一次给 Codex 的任务卡

可以从下面的提示开始：

```text
你是我的办公资料分析助手。先不要写总结。
请完成以下步骤：
1. 列出当前目录中的文件，并说明每个文件可能包含什么信息。
2. 找出重复、冲突、缺失和无法确认的内容。
3. 只引用文件中实际出现的事实，不要补写没有来源的结论。
4. 最后给我一个“下一步应该先查什么”的清单。

输出使用表格，日期、数字、负责人和来源单独列出。
```

### 通过标准

- 输入文件已脱敏，且数量足够支撑一个具体主题。
- Codex 输出了文件清单和信息缺口，而不是直接编造结论。
- 你能指出至少一处需要人工确认的内容。


<a id="02-brief"></a>

## 02 生成可执行的工作简报

资料盘点完成后，再让 Codex 生成一份给同事看的工作简报。简报只保留会影响决策和行动的内容，建议控制在一页或两页。

### 推荐结构

```md
## 项目 / 事项名称

### 一句话结论

### 已确认事实
- 事实：来源：文件名 / 段落或行号

### 当前进展
| 事项 | 状态 | 负责人 | 截止时间 | 来源 |

### 下一步行动
| 优先级 | 动作 | 负责人 | 截止时间 | 依赖 |

### 风险与待确认问题
- 风险或问题：需要谁确认，最晚何时确认
```

### 第二次给 Codex 的任务卡

```text
基于已盘点的资料，生成一份“可执行工作简报”。

要求：
- 先写一句不超过 40 字的结论。
- 把事实、推断、建议分成三个区域。
- 所有日期、数字、负责人都要标注来源；没有来源就写“待确认”。
- 行动项必须包含动作、负责人、截止时间和依赖。
- 将冲突信息列入“风险与待确认问题”，不要自行选择一个版本。
- 最后给出 3 个最值得在下一次会议确认的问题。
```

### 人工抽查

随机挑 5 个关键字段回到原始文件核对：

| 字段 | 简报内容 | 原文内容 | 是否一致 |
| --- | --- | --- | --- |
| 截止时间 |  |  | 通过 / 不通过 |
| 负责人 |  |  | 通过 / 不通过 |
| 数字 |  |  | 通过 / 不通过 |

如果发现错误，不要只手工改结果，回到提示词中补充约束，再生成一次并比较差异。

### 通过标准

- 简报可以被没有参与会议的人读懂。
- 每个行动项都有负责人和时间，或明确标记为待确认。
- 至少完成 5 个关键字段的原文抽查。


<a id="03-review"></a>

## 03 验收与提交打卡

最后用“执行者视角”读一遍简报：如果你明天才接手这个事项，是否知道先做什么、找谁确认、何时回报？

### 验收清单

- [ ] 输入资料已经脱敏，没有客户个人信息和内部凭据。
- [ ] 简报区分了事实、推断、建议和待确认问题。
- [ ] 至少 5 个日期、数字或负责人已经回到原文核对。
- [ ] 行动项可以直接复制进待办工具。
- [ ] 简报中保留了来源，别人能复查关键结论。
- [ ] 删除了没有影响行动的冗余背景。

### 最终交付模板

```md
### 任务
- 我处理的资料主题：
- 输入文件数量：

### 结果
- 一句话结论：
- 最重要的三个行动项：
- 仍待确认的问题：

### 验证
- 我抽查的字段：
- 发现并修正的问题：
- 我没有验证的内容：
```

把简报截图或导出文件，以及上面的过程记录提交到 Workshop 任务。完成打卡前确认截图没有真实姓名、邮箱、电话、内部网址或敏感数字。

通过标准是这份简报能让另一个人继续执行，而不是只证明 Codex 生成过一段文字。
