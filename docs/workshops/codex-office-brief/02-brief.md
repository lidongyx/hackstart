# 02 生成可执行的工作简报

资料盘点完成后，再让 Codex 生成一份给同事看的工作简报。简报只保留会影响决策和行动的内容，建议控制在一页或两页。

## 推荐结构

```md
# 项目 / 事项名称

## 一句话结论

## 已确认事实
- 事实：来源：文件名 / 段落或行号

## 当前进展
| 事项 | 状态 | 负责人 | 截止时间 | 来源 |

## 下一步行动
| 优先级 | 动作 | 负责人 | 截止时间 | 依赖 |

## 风险与待确认问题
- 风险或问题：需要谁确认，最晚何时确认
```

## 第二次给 Codex 的任务卡

```text
基于已盘点的资料，生成一份“可执行工作简报”。

要求：
- 先写一句不超过 40 字的结论。
- 把事实、推断、建议分成三个区域。
- 所有日期、数字、负责人都要标注来源；没有来源就写“待确认”。
- 行动项必须包含动作、负责人、截止时间和依赖。
- 将冲突信息列入“风险与待确认问题”，不要自行选择一个版本。
- 最后给出 3 个最值得在下一次会议确认的问题。
```

## 人工抽查

随机挑 5 个关键字段回到原始文件核对：

| 字段 | 简报内容 | 原文内容 | 是否一致 |
| --- | --- | --- | --- |
| 截止时间 |  |  | 通过 / 不通过 |
| 负责人 |  |  | 通过 / 不通过 |
| 数字 |  |  | 通过 / 不通过 |

如果发现错误，不要只手工改结果，回到提示词中补充约束，再生成一次并比较差异。

## 通过标准

- 简报可以被没有参与会议的人读懂。
- 每个行动项都有负责人和时间，或明确标记为待确认。
- 至少完成 5 个关键字段的原文抽查。
