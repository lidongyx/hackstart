# 用 Codex + GPT Image 2.5 做视觉素材包

这是一个面向内容运营、电商和品牌新人的视觉 Workshop。你会先用 Codex 把模糊需求变成视觉 brief，再使用当前 Codex 环境中的 GPT Image 2.5 生成一套有明确用途和尺寸的素材，最后完成人工检查。

## Workshop 参数

| 参数 | 内容 |
| --- | --- |
| 难度 | 入门，2 / 5 |
| 预计操作时间 | 90-120 分钟 |
| 最终成果 | 1 张主视觉、2 个适配版本、1 份提示词和验收记录 |
| 需要准备 | 一个产品、活动或内容主题，最好有公开可使用的参考素材 |
| 工具 | Codex、GPT Image 2.5、图片预览或简单编辑工具 |

不要把任务理解为“多生成几张图”。你要交付的是一组能放进具体工作流的素材，并能说明哪一张用于什么场景。

## 你要完成的事情

1. 写清受众、用途、画幅、主体和不能出现的元素。
2. 让 Codex 把 brief 转成可执行的图像提示词和检查表。
3. 使用 GPT Image 2.5 生成主视觉，并制作两个尺寸或构图变体。
4. 检查主体、文字、品牌边界和尺寸是否适合发布。
5. 提交图片、提示词和一次失败迭代的复盘。

进入 [01 写视觉 brief](#01-brief) 开始。


<a id="01-brief"></a>

## 01 写清视觉需求

先选一个小而具体的场景，例如“跨境电商新品介绍首图”“课程活动封面”或“公众号文章配图”。不要同时做整套品牌系统。

### 视觉 brief

```text
使用场景：
目标受众：
图片用途：
主主体：
主体动作或状态：
环境与材质：
构图和镜头：
色彩方向：
画幅与尺寸：
必须保留：
不能出现：
参考风格：
```

如果要使用产品图、人物图或品牌元素，确认你有权使用。练习时可用自制物品、公开授权素材或虚构品牌，不要上传客户合同、未发布产品图或未经同意的肖像。

### 用 Codex 生成提示词初稿

```text
请把下面的视觉 brief 转成一份可执行的图像生成任务卡。
输出：
1. 主提示词：主体、动作、环境、构图、光线、材质、色彩、镜头。
2. 负面约束：不要出现的主体、错误文字、变形、杂乱背景和不符合用途的元素。
3. 3 个版本：主视觉、方形社媒图、竖版封面。
4. 每个版本的验收清单。

不要添加 brief 中没有的品牌承诺，不要虚构产品功能。
```

### 通过标准

- 一个外部读者能仅凭 brief 判断图片用途。
- 三个版本有明确画幅和构图差异。
- 提示词没有要求模型生成未经授权的真实人物或品牌资产。


<a id="02-generate"></a>

## 02 生成主视觉与适配版本

在 Codex 中选择 GPT Image 2.5，先生成主视觉，再基于同一 brief 做两个用途不同的适配版本。每次只改变一个主要变量，例如画幅、主体位置或留白方向，方便判断什么改动有效。

### 生成顺序

1. 主视觉：完整表达主题，先确认主体和风格。
2. 方形版本：为社交媒体或商品卡片调整主体占比。
3. 竖版版本：为手机封面或短视频首帧预留标题区域。

保留每次生成的提示词和版本名称，例如：

```text
v1-main-hero
v2-square-social
v3-portrait-cover
```

如果图片中需要文字，把文字作为后期排版任务处理。先确认画面构图和留白，不要把重要文案的正确性完全交给生成模型。

### 用 Codex 做结果检查

可以把三张图和 brief 一起交给 Codex，请它按表格输出检查结果：

| 检查项 | 主视觉 | 方形版 | 竖版 |
| --- | --- | --- | --- |
| 主体是否清楚 |  |  |  |
| 是否符合用途 |  |  |  |
| 是否留出文案区域 |  |  |  |
| 是否有明显变形或错误元素 |  |  |  |
| 是否需要人工修图 |  |  |  |

通过标准不是“看起来很漂亮”，而是每个版本都能放进预定的工作场景，并且知道发布前还要检查什么。


<a id="03-review"></a>

## 03 验收与提交打卡

把图片放进一个接近真实发布的占位页面、商品卡片或视频封面中，检查它在实际尺寸下是否仍然清楚。再找一位没有看过 brief 的人回答：这张图用于什么、主体是什么、是否有明显问题。

### 验收清单

- [ ] 三张图都有明确文件名、用途和尺寸。
- [ ] 主体、数量、颜色和产品外形没有明显错误。
- [ ] 没有未经授权的人脸、商标、客户资料或内部信息。
- [ ] 图片中的文字已经人工校对，关键文案没有直接依赖生成结果。
- [ ] 至少保留了一次失败迭代和修改理由。
- [ ] 导出文件可以被同事直接预览和继续编辑。

### 最终交付模板

```md
### 素材包
- 使用场景：
- 主视觉文件：
- 适配版本：
- 每个版本的用途：

### 生成过程
- 我给 Codex 的 brief：
- 最终提示词：
- 失败迭代及原因：

### 验收
- 我检查过的元素：
- 还需要人工修图或排版的部分：
- 发布前最后一个风险：
```

提交素材截图、提示词摘要和过程记录。不要上传包含未授权人物、客户资料或内部品牌资产的原始参考图。
