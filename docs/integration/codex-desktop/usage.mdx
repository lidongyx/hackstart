# 第5步 Codex 的使用入门

完成下载和 CC Switch 配置后，就可以让 Codex 通过 HackStart API 处理真实项目和真实办公资料了。新人建议先从“读”和“解释”开始，再让它“改”“整理”“生成”和“运行命令”。

## 首次使用要注意什么
Codex第一次打开的时候会比较慢，甚至需要两三分钟，这个过程不要急；打开之后，该如何测试呢？首先要注意Codex有聊天版和项目版，你可以直接创建新的对话，而不是在项目或文件夹里打开，平时使用的时候选择`GPT-5.6`的`Medium`也就是推理级别为“中”就可以。

在你确定HackStart API的配置没有问题后，再打开一个测试项目或测试资料文件夹，对 Codex 说：

```text
请用中文概括这个目录里有哪些文件、它们大概分别用于什么。先不要修改任何文件。
```

成功标准：Codex 能正常返回结果。HackStart 控制台出现请求记录。没有提示模型不存在、401、403 或网络错误。第一次不要直接让它“修复整个项目”“重构所有代码”“批量改全部文档”或“删除无用文件”。先确认配置和模型可用。

## 什么时候用高模型
注意，使用模型的时候，不要使用已经停止支持的旧版模型。更推荐使用`GPT-5.6`，即使推理级别选择`低`，通常也能获得更完整的新模型能力；复杂任务可以再提高推理级别。不同版本和推理级别的能力、速度与成本存在差异，不建议只按价格选择。

以下场景可以使用低成本模型，比如：解释单个文件；写小函数；翻译注释；生成简单文档；简单命令行问题；整理短文档、改写话术、生成邮件草稿和提炼会议要点。

高能力模型适合：大型代码库理解；跨多个文件的重构；难以复现的 bug；架构设计、性能分析、安全审查；长上下文任务；大量资料、会议纪要、竞品信息和报告素材的综合分析；多部门协作流程、营销活动、运营 SOP 和管理汇报的结构化整理。

## 常见报错

### 401 或 Unauthorized

通常是 API Key 错误。

检查：

1. Key 是否复制完整。
2. `auth.json` 里是否有多余空格或中文引号。
3. 是否使用了已经删除或禁用的 Key。
4. CC Switch 当前 Provider 是否切到了 HackStart。

### 403 或 Permission denied

通常是分组、额度或权限问题。

检查：

1. API Key 是否分配了分组。
2. 分组是否允许当前模型。
3. 账户余额是否充足。
4. Key 是否设置了 IP 白名单或额度上限。

### model not found

当前模型名不可用。

处理：

1. 到 HackStart 控制台查看可用模型。
2. 把 `model` 和 `review_model` 改成可用模型。
3. 完整退出并重启 Codex。

### 网络错误

先在浏览器打开：

```text
https://ip2.hackstart.org/health
```

如果浏览器能打开，继续检查：

1. 公司网络是否拦截。
2. 本机代理是否影响 Codex。
3. 杀毒软件或防火墙是否拦截。
4. Base URL 是否写错。

### 配置改了但 Codex 没生效

处理顺序：

1. 在 CC Switch 里确认当前 Provider。
2. 完整退出 Codex。
3. 重新打开 Codex。
4. 新建一个任务测试。
5. 仍不生效时，手动查看 `config.toml`。

## 用量控制建议

- 长任务前先问 Codex 计划，不要一上来让它无限尝试。
- 报错后不要连续点很多次重试，先看控制台是否已经产生请求。
- 给新人测试 Key 设置额度上限。
- 不同客户端使用不同 Key，方便排查谁消耗了额度。
- 大批量生成、图片任务和长上下文任务前，先看模型价格。
