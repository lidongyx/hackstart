# OpenClaw 接入 HackStart

OpenClaw 属于更偏本地 Agent 的工具：它不只是聊天，还会围绕本机任务、代码项目和工具调用组织工作流。相比 Cherry Studio 这类聊天软件，它更适合进阶用户；相比 Codex 桌面端，它通常需要你更理解配置、权限和执行边界。

如果你是新人，建议先完成：

1. [注册与充值](/docs/integration/codex-desktop/register-and-recharge)
2. [Codex 桌面端](/docs/integration/codex-desktop/download)
3. [通用 OpenAI Compatible 聊天客户端](/docs/integration/chat-clients/openai-compatible)

再来配置 OpenClaw。

## 适合什么场景

| 场景 | 是否适合 |
| --- | --- |
| 本地项目分析 | 适合 |
| 多步骤任务规划 | 适合 |
| 工具调用和自动化 | 适合 |
| 新人第一次接入 API | 不建议 |
| 简单聊天问答 | 用 Cherry Studio 更轻 |
| 标准代码任务 | Codex 桌面端或 CLI 更直接 |

## 下载与安装

OpenClaw 的安装入口以项目官方文档或 GitHub 仓库为准：

- 官方网站：[https://openclaw.ai](https://openclaw.ai)
- 官方文档：[https://docs.openclaw.ai](https://docs.openclaw.ai)
- GitHub 仓库：[openclaw/openclaw](https://github.com/openclaw/openclaw)

官方推荐的 CLI 安装方式通常是全局安装并运行 onboard：

```bash
npm install -g openclaw@latest
openclaw onboard --install-daemon
openclaw gateway status
```

如果你使用 pnpm：

```bash
pnpm add -g openclaw@latest
openclaw onboard --install-daemon
```

OpenClaw 官方文档建议使用较新的 Node.js。安装前先检查：

```bash
node --version
npm --version
```

下载或安装时按系统选择：

| 系统 | 注意事项 |
| --- | --- |
| macOS Apple Silicon | 直接使用 npm / pnpm 安装；如有桌面伴侣 App，选择 arm64 / Apple Silicon |
| macOS Intel | 直接使用 npm / pnpm 安装；如有桌面伴侣 App，选择 x64 / Intel |
| Windows | 推荐通过 WSL2 使用 Linux 安装路径；如果官方提供原生 Windows 包，再按官方说明安装 |
| Linux | 使用 npm / pnpm 安装，或按官方 Docker / systemd 文档部署 |

安全建议：

1. 只从项目官网或官方 GitHub 下载。
2. 不使用来源不明的二次打包版本。
3. 第一次使用时打开测试项目。
4. 不要直接授权它操作包含生产密钥的目录。

## Windows 特别说明

OpenClaw 这类本地 Agent 往往会调用 shell、文件系统和后台服务。Windows 新人优先使用 WSL2：

1. 安装 WSL2 和 Ubuntu。
2. 在 Ubuntu 里安装 Node.js。
3. 在 Ubuntu 终端里安装 OpenClaw。
4. 项目也放在 WSL2 文件系统内，例如 `~/projects/my-app`。

不要一半在 Windows PowerShell，一半在 WSL2 里运行同一个项目。路径和权限混用会让排错变复杂。

## OpenAI Compatible 配置

如果 OpenClaw 支持 OpenAI Compatible Provider，按下面填写：

```text
Provider: OpenAI Compatible
Name: HackStart
API Key: sk-...
Base URL: https://ip2.hackstart.org/v1
Model: gpt-5.5
```

如果界面里写的是 Endpoint、API Host 或 Server URL，通常也填：

```text
https://ip2.hackstart.org/v1
```

如果 OpenClaw 明确支持 Codex / Responses Provider，并要求类似 `wire_api = "responses"` 的配置，才使用：

```text
https://ip2.hackstart.org
```

如果你使用 OpenClaw 的模型配置命令或配置文件，目标仍然是同一组值：

```text
provider: openai-compatible
api_key: sk-...
base_url: https://ip2.hackstart.org/v1
model: gpt-5.5
```

字段名以 OpenClaw 当前版本为准。不要把示例里的字段名硬套到不兼容的配置文件里。

## 模型选择

OpenClaw 这类 Agent 工具可能会多轮规划、多次读取文件、多次调用工具。建议：

1. 第一次用低成本模型测试连接。
2. 真正执行复杂任务时再切换高能力模型。
3. 给 OpenClaw 单独创建 API Key。
4. 给这个 Key 设置额度上限。

示例模型：

```text
gpt-5.5
gpt-5.4
gpt-5.4-mini
gpt-5.3-codex
```

以 HackStart 控制台实际可用模型为准。

## 第一次测试

不要让 Agent 直接改项目。先做只读任务：

```text
请读取当前项目，概括目录结构和主要技术栈。不要修改文件，不要运行命令。
```

成功后再允许小范围任务：

```text
请只分析 package.json 和 README，告诉我本地启动步骤。不要修改文件。
```

最后再尝试修改：

```text
请只修改 README 中的安装说明，不要改其它文件。修改后告诉我 diff 摘要。
```

## 权限边界

OpenClaw 这类工具通常能力更强，因此要更严格限制：

- 不要默认允许删除文件。
- 不要默认允许部署。
- 不要默认允许上传项目。
- 不要在生产服务器上直接试验。
- 不要把 API Key 写入项目文件。
- 每次执行命令前先看命令内容。

## 常见问题

### 找不到 OpenAI Compatible

说明当前版本可能不支持自定义 OpenAI Provider。可以更新版本，或改用 VS Code 插件、Codex、Cherry Studio。

### Base URL 不知道填哪个

大多数 OpenAI Compatible 场景填：

```text
https://ip2.hackstart.org/v1
```

只有明确的 Codex / Responses 场景填：

```text
https://ip2.hackstart.org
```

### Agent 循环执行很多轮

立即停止任务，到 HackStart 控制台查看用量。下次任务里明确写：

```text
最多执行 3 轮检查。每轮失败后先总结，不要重复运行同一命令。
```
