# 额度与使用记录

额度和使用记录用来回答两个问题：这个 Key 还能用多少，以及钱花到哪里去了。新人接入 HackStart API 后，必须学会看这两个页面。

## 额度是什么

额度可以理解为这个账号或 API Key 最多能消费的金额。常见形式包括：

| 类型 | 说明 |
| --- | --- |
| 账户余额 | 整个账号可用余额 |
| Key 额度 | 单个 API Key 的消费上限 |
| 速率限制 | 5 小时、1 天、7 天等时间窗口内的消费上限 |
| 分组限制 | 某个模型分组允许的模型和使用规则 |

如果 Key 的额度用完，即使账户还有余额，这个 Key 也可能无法继续请求。

## 查看使用记录

1. 登录 [HackStart 控制台](https://hackstart.org/login)。
2. 进入 API Key 或使用记录页面。
3. 找到对应 Key。
4. 查看最近请求、模型、消耗、状态码和时间。

排查问题时先看使用记录：

- 客户端报错但没有记录：可能请求没有到达 HackStart，优先检查 Base URL、网络和客户端配置。
- 有记录但失败：看状态码和错误信息。
- 有大量记录：可能客户端在循环重试或 Agent 任务过大。

## 最小可用性测试

配置任何客户端后，都先问一个短问题：

```text
请用一句话说明你现在可以正常工作。
```

成功标准：

1. 客户端能返回回答。
2. HackStart 控制台出现请求记录。
3. 用量没有异常暴涨。
4. 当前模型是你选择的模型。

测试成功后，再让客户端执行代码修改、长文总结、批量生成或图片任务。

## 如何判断消耗是否正常

| 现象 | 可能原因 |
| --- | --- |
| 一个短问题消耗很低 | 正常 |
| 长文档总结消耗明显增加 | 输入内容很长，正常 |
| Codex 反复请求很多次 | Agent 在多轮尝试，需要看任务是否失控 |
| 输出很长导致费用高 | 模型输出内容多，可以限制输出长度 |
| 失败请求也有消耗 | 请求已经进入模型处理流程，可能产生费用 |

如果不确定，先停止客户端，再看使用记录，不要连续点击重试。

## 给新人设置额度

建议：

1. 每个新人单独创建 Key。
2. 给测试 Key 设置较低额度。
3. 第一次跑通后再增加额度。
4. 重要任务单独创建 Key。
5. 任务结束后禁用或删除 Key。

这样可以避免一个配置错误消耗整个团队余额。

## 常见额度问题

### 403 或 quota exceeded

通常是 Key 额度、账户余额或速率限制触发。检查：

1. 账户余额是否充足。
2. Key 是否设置了额度上限。
3. Key 是否达到 5 小时、1 天或 7 天速率限制。
4. 当前模型是否属于该 Key 的分组权限。

### model not found

模型名不在当前 Key 可用范围内。换成控制台可见模型，或联系管理员调整分组。

### 控制台没有使用记录

通常说明请求没到 HackStart。检查：

1. Base URL 是否正确。
2. 客户端是否真的选择了 HackStart Provider。
3. 本机网络是否可访问 `https://ip2.hackstart.org/health`。
4. API Key 是否填在正确位置。

## 使用记录排查模板

向团队或管理员求助时，提供这些信息，不要提供 API Key：

```text
客户端名称和版本：
操作系统：
使用的 Base URL：
模型名：
错误码：
错误信息：
控制台是否有使用记录：
大概请求时间：
```

不要截图 API Key。需要排查时，可以创建一个临时低额度 Key，用完删除。
