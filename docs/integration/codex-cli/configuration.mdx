# Codex CLI 配置 HackStart

Codex CLI 使用 HackStart 时，推荐通过 `~/.codex/config.toml` 配置 Provider，通过 `~/.codex/auth.json` 或环境变量保存 API Key。

<H>关键规则</H> Codex CLI 的 Responses Provider 使用：

```text
https://ip2.hackstart.org
```

不要写成：

```text
https://ip2.hackstart.org/v1
```

## 先创建 API Key

1. 打开 [HackStart 控制台](https://hackstart.org/login)。
2. 创建一个 CLI 专用 Key。
3. 名称建议写成 `codex-cli-macbook`、`codex-cli-windows` 或 `codex-cli-server`。
4. 确认 Key 所在分组能使用你要的模型。
5. 复制 Key。

不要复用生产系统的 Key。CLI 经常会在项目里跑命令，单独 Key 更容易限制额度和排查用量。

## macOS / Linux 配置文件

创建配置目录：

```bash
mkdir -p ~/.codex
```

创建或编辑 `~/.codex/config.toml`：

```toml
model_provider = "OpenAI"
model = "gpt-5.5"
review_model = "gpt-5.5"
model_reasoning_effort = "high"
disable_response_storage = true
network_access = "enabled"
model_context_window = 1000000
model_auto_compact_token_limit = 900000

[model_providers.OpenAI]
name = "OpenAI"
base_url = "https://ip2.hackstart.org"
wire_api = "responses"
requires_openai_auth = true
```

创建或编辑 `~/.codex/auth.json`：

```json
{
  "OPENAI_API_KEY": "sk-..."
}
```

如果你不想把 Key 写入文件，也可以在当前终端设置环境变量：

```bash
export OPENAI_API_KEY="sk-..."
```

想长期生效，可以写入 `~/.zshrc`：

```bash
echo 'export OPENAI_API_KEY="sk-..."' >> ~/.zshrc
source ~/.zshrc
```

## Windows 配置文件

配置目录：

```text
%userprofile%\.codex
```

打开方法：

1. 按 `Win + R`。
2. 输入 `%userprofile%\.codex`。
3. 如果目录不存在，创建 `.codex` 文件夹。

创建 `config.toml`：

```toml
model_provider = "OpenAI"
model = "gpt-5.5"
review_model = "gpt-5.5"
model_reasoning_effort = "high"
disable_response_storage = true
network_access = "enabled"
windows_wsl_setup_acknowledged = true
model_context_window = 1000000
model_auto_compact_token_limit = 900000

[model_providers.OpenAI]
name = "OpenAI"
base_url = "https://ip2.hackstart.org"
wire_api = "responses"
requires_openai_auth = true
```

创建 `auth.json`：

```json
{
  "OPENAI_API_KEY": "sk-..."
}
```

PowerShell 临时环境变量写法：

```powershell
$env:OPENAI_API_KEY="sk-..."
```

PowerShell 用户级环境变量写法：

```powershell
[Environment]::SetEnvironmentVariable("OPENAI_API_KEY", "sk-...", "User")
```

写入用户级环境变量后，需要重新打开 PowerShell。

## 使用 CC Switch 导入

如果你已经安装 CC Switch，也可以从 HackStart 控制台的 API Key 页面导入：

1. 点击“导入到 CC Switch”。
2. 选择 `Codex CLI`。
3. 允许浏览器打开 CC Switch。
4. 在 CC Switch 里确认导入。
5. 确认 endpoint 是 `https://ip2.hackstart.org`。

CC Switch 导入后仍建议打开配置文件看一眼，确认 `wire_api = "responses"` 和 `base_url` 没有写错。

## 模型怎么选

示例里使用 `gpt-5.5`，但最终以 HackStart 控制台实际可用模型为准。

常见选择思路：

| 用途 | 推荐 |
| --- | --- |
| 大型项目理解、复杂重构 | 使用高能力模型 |
| 普通代码解释、文档生成 | 使用较低成本模型 |
| 长上下文任务 | 选择上下文更大的模型 |
| 新人试用 | 先用低成本模型验证配置 |

如果提示模型不存在，先换成控制台可见模型，不要反复重试同一个错误模型。

## 配置检查

运行：

```bash
codex --version
```

再进入一个测试项目目录：

```bash
cd /path/to/test-project
codex
```

在 Codex CLI 里输入：

```text
请只概括这个项目的目录结构，不要修改文件。
```

成功后，到 HackStart 控制台检查请求记录。

## 常见错误

### 把 Base URL 写成了 /v1

错误：

```toml
base_url = "https://ip2.hackstart.org/v1"
wire_api = "responses"
```

正确：

```toml
base_url = "https://ip2.hackstart.org"
wire_api = "responses"
```

### API Key 放错地方

确认 `auth.json` 是合法 JSON：

```json
{
  "OPENAI_API_KEY": "sk-..."
}
```

不要写成中文引号，不要在末尾多写逗号。

### 改了配置但没生效

1. 关闭当前 Codex CLI。
2. 重新打开终端。
3. 重新进入项目目录。
4. 再运行 `codex`。

如果你同时用了环境变量和 `auth.json`，先确认它们不是两个不同的 Key。
