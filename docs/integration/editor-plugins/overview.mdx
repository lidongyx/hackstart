# 编辑器插件总览

编辑器插件适合每天写代码的人。它们通常安装在 VS Code、Cursor、JetBrains 等编辑器里，可以读取当前文件、解释选中代码、生成补丁、补全函数、写测试和分析报错。

多数编辑器插件使用 OpenAI Compatible 方式接入 HackStart：

```text
https://ip2.hackstart.org/v1
```

如果某个插件明确支持 Codex Responses Provider，才使用：

```text
https://ip2.hackstart.org
```

## 插件和 Codex 的区别

| 工具 | 适合场景 | 特点 |
| --- | --- | --- |
| Codex 桌面端 | 新人上手、完整项目任务 | 独立 App，围绕项目任务工作 |
| Codex CLI | 终端、服务器、自动化 | 和命令行深度结合 |
| 编辑器插件 | 日常写代码 | 就在编辑器里，适合边写边问 |
| 聊天客户端 | 非代码问答、多模型聊天 | 更像本地 ChatGPT |
| Agent 工具 | 高级自动化、本机工具调用 | 配置更复杂，能力更强 |

## 常见 VS Code 插件类型

| 类型 | 常见代表 | 适合 |
| --- | --- | --- |
| Chat / Agent 插件 | Cline、Roo Code、Kilo Code 等 | 让 AI 读取项目、修改文件、执行命令 |
| 补全插件 | Continue 等 | 代码补全、聊天、局部修改 |
| 自定义 OpenAI 插件 | 各类 OpenAI Compatible 插件 | 快速把 HackStart 当 OpenAI API 使用 |

插件名称和界面会变化，但核心配置通常只有三项：

```text
API Key: sk-...
Base URL: https://ip2.hackstart.org/v1
Model: gpt-5.5
```

## 什么时候选编辑器插件

推荐：

- 你每天主要在 VS Code 或 Cursor 写代码。
- 你希望 AI 看见当前打开的文件。
- 你想对选中代码提问。
- 你希望 AI 生成局部修改或测试。

不推荐作为第一选择：

- 你完全不熟悉编辑器插件权限。
- 你希望 AI 自动完成大型跨项目任务。
- 你还没有弄懂 API Key 和 Base URL。

这时先用 Codex 桌面端或 Cherry Studio 熟悉基本接入。

## 安全注意事项

编辑器插件可能读取工作区文件，也可能执行命令。新人务必注意：

1. 不要在包含生产密钥的仓库里随便授权插件全项目读取。
2. 插件提出运行命令时，先看命令内容。
3. 不要允许插件自动提交、自动部署，除非你明确知道后果。
4. 第一次使用时，打开一个测试项目。
5. API Key 使用单独的编辑器插件 Key，并设置额度上限。
