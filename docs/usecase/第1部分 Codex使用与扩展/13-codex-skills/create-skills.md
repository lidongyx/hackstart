# 创建技能

创建技能时，应先写清名称、描述和适用场景。

## 官方内容整理

- 创建技能时，应先写清名称、描述和适用场景。
- 技能正文要完整说明工作流，但不要把无关参考全部塞进主文件。
- 如果有稳定脚本，应放进 scripts，而不是每次让 Codex 重写。
- 模板和 assets 可以提高重复产物的一致性。
- 创建后应使用真实任务试跑，检查是否按预期触发。

## 实践补充

- 从一次成功任务中提炼通用步骤。
- 把“必须做、不要做、如何验证”写清楚。
- 技能更新后需要重新加载或新线程验证。

## 推荐工作流

1. 先明确任务目标、输入来源和允许 Codex 使用的工具。
2. 让 Codex 输出计划、风险边界和需要你确认的问题。
3. 从小范围样例开始，确认方向后再扩大。
4. 要求 Codex 保留证据、文件路径、截图、命令输出或验证结果。
5. 对发送、删除、付款、发布、提交、部署等动作保持人工确认。

## 示例提示词

```text
请帮我创建一个 skill，用来把产品反馈整理成 PRD。设计 SKILL.md 结构、references、scripts、输出模板和测试任务。
```
