# 自动化

![Codex 创建自动化](https://md-1251009918.cos.ap-shanghai.myqcloud.com/hackstart/codex-docs/images-codex-app-create-automation-light.webp)

自动化可以让 Codex 按计划执行重复任务。项目自动化适合定期生成新任务；线程自动化会回到同一线程，保留上下文继续检查。

## 官方内容整理

- 自动化可以让 Codex 按计划执行重复任务。项目自动化适合定期生成新任务；线程自动化会回到同一线程，保留上下文继续检查。
- 持续需要同一上下文的工作，例如长期客户跟踪、指标检查、定期错误评估，适合线程自动化。
- Git 项目里的自动化通常在专用后台 worktree 中运行，减少和你当前本地工作冲突。
- 自动化适合产出可审阅报告、草稿、检查结果或待办，而不适合直接执行高风险动作。

## 实践补充

- 先人工运行几轮，校准输入、输出和风险边界，再开启定时。
- 把自动化输出设计成“需要我注意的变化”，否则很容易变成噪音。
- 所有发送、删除、发布、付款和承诺动作都应保留人工确认。

## 推荐工作流

1. 先明确任务目标、输入来源和允许 Codex 使用的工具。
2. 让 Codex 输出计划、风险边界和需要你确认的问题。
3. 从小范围样例开始，确认方向后再扩大。
4. 要求 Codex 保留证据、文件路径、截图、命令输出或验证结果。
5. 对发送、删除、付款、发布、提交、部署等动作保持人工确认。

## 示例提示词

```text
请把这个重复流程整理成 Codex 自动化任务。输出触发频率、输入来源、处理步骤、输出格式、人工确认点、停止条件和首次试运行检查清单。
```
