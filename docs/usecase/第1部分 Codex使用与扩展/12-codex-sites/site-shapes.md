# 选择站点形态

![Sites 项目列表](https://md-1251009918.cos.ap-shanghai.myqcloud.com/hackstart/codex-docs/images-codex-sites-sites-list-light.jpg)

Sites 支持内容型网站、带结构化数据的应用、文件上传应用、内部身份访问站点和外部认证应用。

## 官方内容整理

- Sites 支持内容型网站、带结构化数据的应用、文件上传应用、内部身份访问站点和外部认证应用。
- 保存记录、用户进度或游戏分数时需要数据库。
- 图片、文档、音频、视频和上传文件需要对象存储。
- 上传文件带可搜索元数据时，通常需要数据库保存元数据、对象存储保存文件。
- 临时 UI 状态不应使用持久存储。

## 实践补充

- 从产品行为倒推数据需求。
- 能不用持久存储就先不用。
- 内部站点要优先使用工作区身份和最小可访问范围。

## 推荐工作流

1. 先明确任务目标、输入来源和允许 Codex 使用的工具。
2. 让 Codex 输出计划、风险边界和需要你确认的问题。
3. 从小范围样例开始，确认方向后再扩大。
4. 要求 Codex 保留证据、文件路径、截图、命令输出或验证结果。
5. 对发送、删除、付款、发布、提交、部署等动作保持人工确认。

## 示例提示词

```text
请根据这个应用需求选择 Sites 站点形态。判断是否需要数据库、对象存储、workspace 身份、公开登录和环境变量，并说明原因。
```
