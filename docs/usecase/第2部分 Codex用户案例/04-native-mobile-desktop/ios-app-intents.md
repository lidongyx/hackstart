# 添加 iOS App Intents

把应用动作和内容暴露给 Shortcuts、Siri、Spotlight 等系统入口。

## 场景定位

这个案例属于“移动与桌面原生开发”。它适合把一个经常需要人工整理、判断或验证的流程交给 Codex 做第一轮处理，然后由你审阅关键结果。

| 项目 | 内容 |
| --- | --- |
| 适合任务 | 把应用动作和内容暴露给 Shortcuts、Siri、Spotlight 等系统入口。 |
| 常用能力 | App Intents、Shortcuts、Siri |
| 产出形态 | 清单、草稿、补丁、报告、截图、表格或可运行原型，取决于具体任务 |

## 适合谁

- 希望用户通过系统快捷方式触发应用动作
- 应用有稳定的核心操作
- 需要接入系统智能能力

## Codex 可以帮你做什么

- 识别适合暴露的动作
- 定义 intent 参数和返回值
- 处理错误和权限
- 编写测试或手动验证步骤

## 推荐工作流

1. 选择一个窄动作开始
2. 确认参数来自稳定数据模型
3. 处理缺失数据和权限错误
4. 在 Shortcuts 中验证
5. 记录系统版本要求

## 示例提示词

```text
请为这个 iOS 应用添加 App Intent。目标是让用户能通过 Shortcuts 创建一个新任务并打开详情页。实现后说明 intent 参数、错误处理和测试方式。
```

## 案例重点展开

- 先从用户真正想在系统外触发的动作和实体开始，而不是暴露所有页面。
- AppIntent、AppEntity 和 AppShortcutsProvider 要围绕稳定数据模型设计。
- 系统入口包括 Shortcuts、Siri、Spotlight 和更广泛的系统体验。
- 第一个 intent surface 应该很小，便于测试和迭代。
- 把它看成 assistant infrastructure，而不只是快捷指令功能。

## 完整用法拆解

### 1. 先把任务范围说清楚

这个案例的重点不是让 Codex 猜你的真实需求，而是把“把应用动作和内容暴露给 Shortcuts、Siri、Spotlight 等系统入口。”拆成一组可以检查的步骤。开始时先说明输入来源、时间范围、目标对象和最终产物。如果任务涉及多个工具，也要告诉 Codex 哪些工具可以读、哪些动作只能准备草稿。

可以把范围写成三句话：我要处理什么资料、希望得到什么结果、哪些事情不能自动执行。对于“移动与桌面原生开发”这类任务，范围越清楚，Codex 越容易把注意力放在真正有价值的判断上。

### 2. 让 Codex 先输出中间结果

不要一上来要求最终答案。更稳妥的方式是先让 Codex 完成“识别适合暴露的动作”，再让它解释判断依据。这样你可以在中间阶段纠偏，避免它把不重要的信息写进最终产物。

如果任务比较长，可以要求 Codex 先给你一个小型样例，例如前 5 条记录、前 3 个页面、一个模块或一封邮件。样例通过后，再扩大到完整范围。

### 3. 把工具和证据写进交付物

这个场景常用能力包括：App Intents、Shortcuts、Siri。让 Codex 使用这些能力时，最好要求它把依据也写出来：读了哪些文件、参考了哪些消息、运行了哪些命令、看到哪些截图或日志。

证据不是为了增加篇幅，而是为了让你能判断结果是否可靠。特别是 希望用户通过系统快捷方式触发应用动作，更应该看到来源、假设和未确认问题。

### 4. 逐轮校准，而不是一次到位

第一次结果通常是校准样本。你可以告诉 Codex 哪些判断正确、哪些内容太泛、哪些边界必须更严格。经过几轮之后，再考虑把流程保存为技能、自动化或长期 goal。

一个可用的校准顺序是：选择一个窄动作开始；确认参数来自稳定数据模型；最后 记录系统版本要求。这样既能提高产出质量，也能减少误操作。

## 更多提示词案例

### 入门版

```text
请为这个 iOS 应用添加 App Intent。目标是让用户能通过 Shortcuts 创建一个新任务并打开详情页。实现后说明 intent 参数、错误处理和测试方式。

请先只处理一个小范围样例，并说明你的判断依据、输出结构和需要我确认的问题。
```

### 进阶版

```text
请把“添加 iOS App Intents”作为一个完整工作流来执行。
目标：把应用动作和内容暴露给 Shortcuts、Siri、Spotlight 等系统入口。
可用能力：App Intents、Shortcuts、Siri
请按以下步骤进行：
1. 先确认输入来源和任务范围。
2. 输出执行计划和风险边界。
3. 生成第一版结果。
4. 标注每个关键结论的依据。
5. 列出需要我确认的问题。
不要执行发送、删除、付款、发布、承诺等不可逆动作。
```

### 复盘版

```text
请复盘刚才这次“添加 iOS App Intents”任务。
请输出：
1. 哪些输入最有用；
2. 哪些判断仍然不确定；
3. 哪些步骤可以下次自动化；
4. 哪些动作必须继续人工确认；
5. 下一次我应该怎样给你更好的上下文。
```

### 自动化前校准版

```text
我想把这个流程以后重复使用，但现在先不要自动化。
请根据本次任务整理一个可复用流程：触发条件、输入来源、处理步骤、输出格式、验证方式、停止条件和人工确认点。
尤其注意：Intent 不应依赖临时 UI 状态。
```

## 交付物检查清单

完成这类任务后，建议检查以下内容：

- 是否清楚说明了输入来源、处理范围和时间范围。
- 是否把“识别适合暴露的动作”和“定义 intent 参数和返回值”的依据写出来。
- 是否列出了不确定信息、缺失材料和需要你确认的问题。
- 是否避免了越权动作，尤其是发送、删除、付款、发布、承诺和修改生产数据。
- 是否留下了下一步可以继续执行的清单、文件、补丁、报告或验证结果。

## 使用边界

- Intent 不应依赖临时 UI 状态
- 系统版本兼容要说明
- 快捷方式入口需要真实验证
