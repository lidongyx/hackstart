# 管理收件箱

让 Codex 检查邮件，找出真正需要你回复的内容，并根据你的语气准备可审阅草稿。

## 场景定位

这个案例属于“日常协作与办公自动化”。它适合把一个经常需要人工整理、判断或验证的流程交给 Codex 做第一轮处理，然后由你审阅关键结果。

| 项目 | 内容 |
| --- | --- |
| 适合任务 | 让 Codex 检查邮件，找出真正需要你回复的内容，并根据你的语气准备可审阅草稿。 |
| 常用能力 | Gmail、Slack、Google Drive、自动化 |
| 产出形态 | 清单、草稿、补丁、报告、截图、表格或可运行原型，取决于具体任务 |

## 适合谁

- 邮件太多、只想看需要行动的部分
- 需要用自己的语气回复客户、同事或合作方
- 希望把定期收件箱清理变成可审阅流程

## Codex 可以帮你做什么

- 扫描指定时间范围或标签下的邮件
- 判断哪些邮件需要回复、哪些只是通知
- 从最近已发送邮件或写作样例中学习语气
- 在缺少背景时去团队消息或文档里补充上下文

## 推荐工作流

1. 明确邮件范围，例如今天、过去一周、某个标签或某个客户
2. 要求 Codex 先输出待处理队列，而不是直接写长文
3. 逐条审阅草稿并告诉它哪些应该忽略
4. 当草稿质量稳定后，再让它定时检查
5. 始终保留“不要发送，只写草稿”的边界

## 示例提示词

```text
请检查我的邮箱，找出需要我回复的邮件，并用我的语气写好草稿。缺少背景时请参考团队消息和文档。不要发送任何邮件，只输出待审阅草稿、优先级和你使用的上下文。
```

## 案例重点展开

- 先让 Codex 做第一轮收件箱盘点，把需要回复、可以等待、纯通知三类分开。
- 用最近已发送邮件或写作样例校准语气，并让 Codex 标明草稿参考了哪些上下文。
- 如果邮件提到项目、客户、文件或阻塞点，让 Codex 去团队消息和文档里补背景。
- 当判断稳定后，可以让同一个线程按固定时间检查新邮件，但仍只生成草稿。
- 整理邮箱、归档或打标签要作为独立指令处理，不要和回复草稿混在一起。

## 完整用法拆解

### 1. 先把任务范围说清楚

这个案例的重点不是让 Codex 猜你的真实需求，而是把“让 Codex 检查邮件，找出真正需要你回复的内容，并根据你的语气准备可审阅草稿。”拆成一组可以检查的步骤。开始时先说明输入来源、时间范围、目标对象和最终产物。如果任务涉及多个工具，也要告诉 Codex 哪些工具可以读、哪些动作只能准备草稿。

可以把范围写成三句话：我要处理什么资料、希望得到什么结果、哪些事情不能自动执行。对于“日常协作与办公自动化”这类任务，范围越清楚，Codex 越容易把注意力放在真正有价值的判断上。

### 2. 让 Codex 先输出中间结果

不要一上来要求最终答案。更稳妥的方式是先让 Codex 完成“扫描指定时间范围或标签下的邮件”，再让它解释判断依据。这样你可以在中间阶段纠偏，避免它把不重要的信息写进最终产物。

如果任务比较长，可以要求 Codex 先给你一个小型样例，例如前 5 条记录、前 3 个页面、一个模块或一封邮件。样例通过后，再扩大到完整范围。

### 3. 把工具和证据写进交付物

这个场景常用能力包括：Gmail、Slack、Google Drive、自动化。让 Codex 使用这些能力时，最好要求它把依据也写出来：读了哪些文件、参考了哪些消息、运行了哪些命令、看到哪些截图或日志。

证据不是为了增加篇幅，而是为了让你能判断结果是否可靠。特别是 邮件太多、只想看需要行动的部分，更应该看到来源、假设和未确认问题。

### 4. 逐轮校准，而不是一次到位

第一次结果通常是校准样本。你可以告诉 Codex 哪些判断正确、哪些内容太泛、哪些边界必须更严格。经过几轮之后，再考虑把流程保存为技能、自动化或长期 goal。

一个可用的校准顺序是：明确邮件范围，例如今天、过去一周、某个标签或某个客户；要求 Codex 先输出待处理队列，而不是直接写长文；最后 始终保留“不要发送，只写草稿”的边界。这样既能提高产出质量，也能减少误操作。

## 更多提示词案例

### 入门版

```text
请检查我的邮箱，找出需要我回复的邮件，并用我的语气写好草稿。缺少背景时请参考团队消息和文档。不要发送任何邮件，只输出待审阅草稿、优先级和你使用的上下文。

请先只处理一个小范围样例，并说明你的判断依据、输出结构和需要我确认的问题。
```

### 进阶版

```text
请把“管理收件箱”作为一个完整工作流来执行。
目标：让 Codex 检查邮件，找出真正需要你回复的内容，并根据你的语气准备可审阅草稿。
可用能力：Gmail、Slack、Google Drive、自动化
请按以下步骤进行：
1. 先确认输入来源和任务范围。
2. 输出执行计划和风险边界。
3. 生成第一版结果。
4. 标注每个关键结论的依据。
5. 列出需要我确认的问题。
不要执行发送、删除、付款、发布、承诺等不可逆动作。
```

### 复盘版

```text
请复盘刚才这次“管理收件箱”任务。
请输出：
1. 哪些输入最有用；
2. 哪些判断仍然不确定；
3. 哪些步骤可以下次自动化；
4. 哪些动作必须继续人工确认；
5. 下一次我应该怎样给你更好的上下文。
```

### 自动化前校准版

```text
我想把这个流程以后重复使用，但现在先不要自动化。
请根据本次任务整理一个可复用流程：触发条件、输入来源、处理步骤、输出格式、验证方式、停止条件和人工确认点。
尤其注意：发送、归档、删除邮件前必须再次确认。
```

## 交付物检查清单

完成这类任务后，建议检查以下内容：

- 是否清楚说明了输入来源、处理范围和时间范围。
- 是否把“扫描指定时间范围或标签下的邮件”和“判断哪些邮件需要回复、哪些只是通知”的依据写出来。
- 是否列出了不确定信息、缺失材料和需要你确认的问题。
- 是否避免了越权动作，尤其是发送、删除、付款、发布、承诺和修改生产数据。
- 是否留下了下一步可以继续执行的清单、文件、补丁、报告或验证结果。

## 使用边界

- 发送、归档、删除邮件前必须再次确认
- 第一次使用时要校准什么算重要邮件
- 涉及合同、报价、法律或人事内容时只做草稿
