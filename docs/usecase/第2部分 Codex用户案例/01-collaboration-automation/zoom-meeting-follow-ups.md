# 把 Zoom 会议变成跟进行动

从会议摘要或转录中提炼客户问题、承诺事项、内部任务和跟进邮件草稿。

## 场景定位

这个案例属于“日常协作与办公自动化”。它适合把一个经常需要人工整理、判断或验证的流程交给 Codex 做第一轮处理，然后由你审阅关键结果。

| 项目 | 内容 |
| --- | --- |
| 适合任务 | 从会议摘要或转录中提炼客户问题、承诺事项、内部任务和跟进邮件草稿。 |
| 常用能力 | Zoom、会议摘要、客户跟进 |
| 产出形态 | 清单、草稿、补丁、报告、截图、表格或可运行原型，取决于具体任务 |

## 适合谁

- 会议之后需要快速形成后续动作
- 客户成功、销售、咨询或产品访谈频繁
- 会议记录里有大量未结构化内容

## Codex 可以帮你做什么

- 提取会议结论和行动项
- 区分对外邮件和内部任务
- 生成客户跟进草稿
- 列出缺失信息和待确认问题

## 推荐工作流

1. 提供会议摘要、转录或 AI Companion 笔记
2. 说明参会方和会议目标
3. 要求输出内外分离的结果
4. 对客户邮件草稿做人工审阅
5. 把未确认内容放进问题列表

## 示例提示词

```text
请根据这次会议摘要生成跟进材料：客户关心的问题、我们承诺的事项、内部需要处理的任务、给客户的邮件草稿、以及不确定或需要确认的信息。
```

## 案例重点展开

- 先从 Zoom 摘要、转录和相关资料生成第一版 follow-up package。
- 给 Codex 足够上下文：客户、议题、上次承诺、相关文件和 Slack 讨论。
- 行动前审阅客户邮件、内部任务、承诺和未确认问题。
- 对 recurring meetings，可以把会议智能整理做成自动化。
- 始终区分对外沟通和内部待办。

## 完整用法拆解

### 1. 先把任务范围说清楚

这个案例的重点不是让 Codex 猜你的真实需求，而是把“从会议摘要或转录中提炼客户问题、承诺事项、内部任务和跟进邮件草稿。”拆成一组可以检查的步骤。开始时先说明输入来源、时间范围、目标对象和最终产物。如果任务涉及多个工具，也要告诉 Codex 哪些工具可以读、哪些动作只能准备草稿。

可以把范围写成三句话：我要处理什么资料、希望得到什么结果、哪些事情不能自动执行。对于“日常协作与办公自动化”这类任务，范围越清楚，Codex 越容易把注意力放在真正有价值的判断上。

### 2. 让 Codex 先输出中间结果

不要一上来要求最终答案。更稳妥的方式是先让 Codex 完成“提取会议结论和行动项”，再让它解释判断依据。这样你可以在中间阶段纠偏，避免它把不重要的信息写进最终产物。

如果任务比较长，可以要求 Codex 先给你一个小型样例，例如前 5 条记录、前 3 个页面、一个模块或一封邮件。样例通过后，再扩大到完整范围。

### 3. 把工具和证据写进交付物

这个场景常用能力包括：Zoom、会议摘要、客户跟进。让 Codex 使用这些能力时，最好要求它把依据也写出来：读了哪些文件、参考了哪些消息、运行了哪些命令、看到哪些截图或日志。

证据不是为了增加篇幅，而是为了让你能判断结果是否可靠。特别是 会议之后需要快速形成后续动作，更应该看到来源、假设和未确认问题。

### 4. 逐轮校准，而不是一次到位

第一次结果通常是校准样本。你可以告诉 Codex 哪些判断正确、哪些内容太泛、哪些边界必须更严格。经过几轮之后，再考虑把流程保存为技能、自动化或长期 goal。

一个可用的校准顺序是：提供会议摘要、转录或 AI Companion 笔记；说明参会方和会议目标；最后 把未确认内容放进问题列表。这样既能提高产出质量，也能减少误操作。

```text
请把“把 Zoom 会议变成跟进行动”作为一个完整工作流来执行。
目标：从会议摘要或转录中提炼客户问题、承诺事项、内部任务和跟进邮件草稿。
```

```text
尤其注意：外发内容必须人工审阅。
```

## 交付物检查清单

完成这类任务后，建议检查以下内容：

- 是否清楚说明了输入来源、处理范围和时间范围。
- 是否把“提取会议结论和行动项”和“区分对外邮件和内部任务”的依据写出来。
- 是否列出了不确定信息、缺失材料和需要你确认的问题。
- 是否避免了越权动作，尤其是发送、删除、付款、发布、承诺和修改生产数据。
- 是否留下了下一步可以继续执行的清单、文件、补丁、报告或验证结果。

## 使用边界

- 外发内容必须人工审阅
- 内部判断不要写进客户邮件
- 转录可能有识别错误，要保留待确认项
