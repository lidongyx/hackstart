# 准备会议简报

根据日历、邮件、文档和上次会议记录生成会前简报、议程和准备清单。

## 场景定位

这个案例属于“团队知识与运营”。它适合把一个经常需要人工整理、判断或验证的流程交给 Codex 做第一轮处理，然后由你审阅关键结果。

| 项目 | 内容 |
| --- | --- |
| 适合任务 | 根据日历、邮件、文档和上次会议记录生成会前简报、议程和准备清单。 |
| 常用能力 | 会议准备、Calendar、知识整理 |
| 产出形态 | 清单、草稿、补丁、报告、截图、表格或可运行原型，取决于具体任务 |

## 适合谁

- 会议前需要快速恢复上下文
- 参会人和资料很多
- 想提前知道风险和问题

## Codex 可以帮你做什么

- 整理参会人和背景
- 回顾上次结论和行动项
- 生成议程和准备材料
- 列出需要确认的问题

## 推荐工作流

1. 提供会议对象和时间
2. 指定可用资料来源
3. 区分事实、推断和建议
4. 保留待确认信息
5. 会后可继续生成跟进

## 示例提示词

```text
请为明天的这个会议准备简报。包括参会人、背景、上次结论、待讨论问题、我需要准备的材料和建议议程。未知信息列为待确认。
```

## 案例重点展开

- 只使用你指定的来源：日历、Drive、Slack、Gmail 或会议记录。
- 简报应短而可扫读，包括目标、背景、问题和笔记模板。
- 来源支持的上下文放前面，推断和建议分开。
- 适合会议前快速恢复上下文。
- 会后可以继续转成 follow-up 或 PRD。

## 完整用法拆解

### 1. 先把任务范围说清楚

这个案例的重点不是让 Codex 猜你的真实需求，而是把“根据日历、邮件、文档和上次会议记录生成会前简报、议程和准备清单。”拆成一组可以检查的步骤。开始时先说明输入来源、时间范围、目标对象和最终产物。如果任务涉及多个工具，也要告诉 Codex 哪些工具可以读、哪些动作只能准备草稿。

可以把范围写成三句话：我要处理什么资料、希望得到什么结果、哪些事情不能自动执行。对于“团队知识与运营”这类任务，范围越清楚，Codex 越容易把注意力放在真正有价值的判断上。

### 2. 让 Codex 先输出中间结果

不要一上来要求最终答案。更稳妥的方式是先让 Codex 完成“整理参会人和背景”，再让它解释判断依据。这样你可以在中间阶段纠偏，避免它把不重要的信息写进最终产物。

如果任务比较长，可以要求 Codex 先给你一个小型样例，例如前 5 条记录、前 3 个页面、一个模块或一封邮件。样例通过后，再扩大到完整范围。

### 3. 把工具和证据写进交付物

这个场景常用能力包括：会议准备、Calendar、知识整理。让 Codex 使用这些能力时，最好要求它把依据也写出来：读了哪些文件、参考了哪些消息、运行了哪些命令、看到哪些截图或日志。

证据不是为了增加篇幅，而是为了让你能判断结果是否可靠。特别是 会议前需要快速恢复上下文，更应该看到来源、假设和未确认问题。

### 4. 逐轮校准，而不是一次到位

第一次结果通常是校准样本。你可以告诉 Codex 哪些判断正确、哪些内容太泛、哪些边界必须更严格。经过几轮之后，再考虑把流程保存为技能、自动化或长期 goal。

一个可用的校准顺序是：提供会议对象和时间；指定可用资料来源；最后 会后可继续生成跟进。这样既能提高产出质量，也能减少误操作。

## 更多提示词案例

### 入门版

```text
请为明天的这个会议准备简报。包括参会人、背景、上次结论、待讨论问题、我需要准备的材料和建议议程。未知信息列为待确认。

请先只处理一个小范围样例，并说明你的判断依据、输出结构和需要我确认的问题。
```

### 进阶版

```text
请把“准备会议简报”作为一个完整工作流来执行。
目标：根据日历、邮件、文档和上次会议记录生成会前简报、议程和准备清单。
可用能力：会议准备、Calendar、知识整理
请按以下步骤进行：
1. 先确认输入来源和任务范围。
2. 输出执行计划和风险边界。
3. 生成第一版结果。
4. 标注每个关键结论的依据。
5. 列出需要我确认的问题。
不要执行发送、删除、付款、发布、承诺等不可逆动作。
```

### 复盘版

```text
请复盘刚才这次“准备会议简报”任务。
请输出：
1. 哪些输入最有用；
2. 哪些判断仍然不确定；
3. 哪些步骤可以下次自动化；
4. 哪些动作必须继续人工确认；
5. 下一次我应该怎样给你更好的上下文。
```

### 自动化前校准版

```text
我想把这个流程以后重复使用，但现在先不要自动化。
请根据本次任务整理一个可复用流程：触发条件、输入来源、处理步骤、输出格式、验证方式、停止条件和人工确认点。
尤其注意：不要把推断当事实。
```

## 交付物检查清单

完成这类任务后，建议检查以下内容：

- 是否清楚说明了输入来源、处理范围和时间范围。
- 是否把“整理参会人和背景”和“回顾上次结论和行动项”的依据写出来。
- 是否列出了不确定信息、缺失材料和需要你确认的问题。
- 是否避免了越权动作，尤其是发送、删除、付款、发布、承诺和修改生产数据。
- 是否留下了下一步可以继续执行的清单、文件、补丁、报告或验证结果。

## 使用边界

- 不要把推断当事实
- 外部会议需要注意保密边界
- 议程需要主持人最终确认
