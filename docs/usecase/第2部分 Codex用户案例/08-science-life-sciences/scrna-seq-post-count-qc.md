# 标注 scRNA-seq 数据

辅助单细胞 RNA-seq 的 post-count QC、注释、UMAP 检查和报告整理。

## 场景定位

这个案例属于“科研与生命科学”。它适合把一个经常需要人工整理、判断或验证的流程交给 Codex 做第一轮处理，然后由你审阅关键结果。

| 项目 | 内容 |
| --- | --- |
| 适合任务 | 辅助单细胞 RNA-seq 的 post-count QC、注释、UMAP 检查和报告整理。 |
| 常用能力 | scRNA-seq、QC、UMAP、细胞注释 |
| 产出形态 | 清单、草稿、补丁、报告、截图、表格或可运行原型，取决于具体任务 |

## 适合谁

- 需要复核单细胞分析结果
- 想把 QC 和注释过程整理成报告
- 有多个 cluster 需要解释

## Codex 可以帮你做什么

- 检查 QC 指标和过滤阈值
- 阅读 marker 基因和 cluster 注释
- 对照 UMAP 可视化
- 输出需要人工复核的点

## 推荐工作流

1. 提供分析结果、marker 表和图
2. 让 Codex 分开写事实和解释
3. 标记低置信注释
4. 保留异常 cluster
5. 由领域专家最终确认

## 示例提示词

```text
请检查这个 scRNA-seq 分析结果。重点看 QC 指标、细胞类型注释、UMAP、异常 cluster 和需要人工复核的标记基因。输出一份可审阅报告。
```

## 案例重点展开

- 以 post-count QC 为起点，检查过滤、聚类、注释和 UMAP。
- 返回内容应包括质量问题、候选细胞类型、marker 证据和复核点。
- NGS Analysis 类技能适合把流程拆成标准检查步骤。
- 结果中要区分数据事实、注释推断和需要实验专家确认的地方。
- 后续可以继续检查输入、mapping 统计和下游差异分析。

## 完整用法拆解

### 1. 先把任务范围说清楚

这个案例的重点不是让 Codex 猜你的真实需求，而是把“辅助单细胞 RNA-seq 的 post-count QC、注释、UMAP 检查和报告整理。”拆成一组可以检查的步骤。开始时先说明输入来源、时间范围、目标对象和最终产物。如果任务涉及多个工具，也要告诉 Codex 哪些工具可以读、哪些动作只能准备草稿。

可以把范围写成三句话：我要处理什么资料、希望得到什么结果、哪些事情不能自动执行。对于“科研与生命科学”这类任务，范围越清楚，Codex 越容易把注意力放在真正有价值的判断上。

### 2. 让 Codex 先输出中间结果

不要一上来要求最终答案。更稳妥的方式是先让 Codex 完成“检查 QC 指标和过滤阈值”，再让它解释判断依据。这样你可以在中间阶段纠偏，避免它把不重要的信息写进最终产物。

如果任务比较长，可以要求 Codex 先给你一个小型样例，例如前 5 条记录、前 3 个页面、一个模块或一封邮件。样例通过后，再扩大到完整范围。

### 3. 把工具和证据写进交付物

这个场景常用能力包括：scRNA-seq、QC、UMAP、细胞注释。让 Codex 使用这些能力时，最好要求它把依据也写出来：读了哪些文件、参考了哪些消息、运行了哪些命令、看到哪些截图或日志。

证据不是为了增加篇幅，而是为了让你能判断结果是否可靠。特别是 需要复核单细胞分析结果，更应该看到来源、假设和未确认问题。

### 4. 逐轮校准，而不是一次到位

第一次结果通常是校准样本。你可以告诉 Codex 哪些判断正确、哪些内容太泛、哪些边界必须更严格。经过几轮之后，再考虑把流程保存为技能、自动化或长期 goal。

一个可用的校准顺序是：提供分析结果、marker 表和图；让 Codex 分开写事实和解释；最后 由领域专家最终确认。这样既能提高产出质量，也能减少误操作。

## 交付物检查清单

完成这类任务后，建议检查以下内容：

- 是否清楚说明了输入来源、处理范围和时间范围。
- 是否把“检查 QC 指标和过滤阈值”和“阅读 marker 基因和 cluster 注释”的依据写出来。
- 是否列出了不确定信息、缺失材料和需要你确认的问题。
- 是否避免了越权动作，尤其是发送、删除、付款、发布、承诺和修改生产数据。
- 是否留下了下一步可以继续执行的清单、文件、补丁、报告或验证结果。

## 使用边界

- 细胞注释必须人工确认
- marker 解释依赖组织和实验背景
- 不要删除异常 cluster 而不说明
