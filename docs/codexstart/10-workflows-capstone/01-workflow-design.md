# 设计一条可复用工作流

## 工作流五要素

1. **触发器**：什么时候开始。
2. **输入**：需要哪些资料和权限。
3. **步骤**：按什么顺序执行。
4. **输出**：交付哪些文件、报告或页面。
5. **异常**：什么时候暂停、回滚或交给人处理。

## 示例：每周内容复盘

```text
触发器：每周五下午，或手动输入“开始复盘”。
输入：本周任务清单、发布内容、数据摘要和未完成事项。
步骤：汇总事实 -> 识别完成与延误 -> 提取问题 -> 生成下周建议。
输出：一页 HTML 复盘、行动项表、待确认问题。
异常：数据缺失、来源冲突、涉及外部发送时暂停。
```

## 从 Prompt 到 Skill 再到自动化

先用 Prompt 跑通一次，再把稳定步骤写成 Skill；如果输入输出已经结构化，再考虑 CLI 或定时任务。不要一开始就把不稳定的流程自动触发。

## 课后任务

设计一条“资料收集到发布”的工作流，标出至少 3 个必须人工确认的节点。
