# 把重复工作做成 Skill

## 什么时候值得做成 Skill

满足下面三项中的两项，就值得考虑：

- 你已经重复做过至少三次。
- 每次都有类似步骤和验证方式。
- 你希望别人也能按照同样标准完成。

## 最小结构

```text
my-skill/
  SKILL.md
```

`SKILL.md` 至少要写清：什么时候使用、什么时候不要使用、执行步骤、输入输出、验证方式和风险边界。

## 一个文档检查 Skill 的骨架

```md
---
name: docs-check
description: 修改 Docusaurus 文档后检查链接、侧边栏、类型和构建。
---

使用时：
1. 先阅读项目 AGENTS.md。
2. 查看 git diff 和文档目录。
3. 检查 front matter 与侧边栏结构。
4. 运行项目要求的验证命令。
5. 输出改动、命令、结果和剩余风险。

不要：
- 修改用户未授权的线上配置；
- 删除已有文档；
- 把警告写成通过。
```

## 好 Skill 的特征

- 触发场景具体，不写“适用于所有任务”。
- 过程可执行，不只是经验口号。
- 验证命令真实存在。
- 长资料放参考文件，不把主文件写成百科。
- 明确失败和暂停条件。

## 课后任务

把你最常用的一段 Prompt 改成 Skill 草稿，并让 Codex 用一个样例执行。根据执行结果删掉无用描述，补上缺失的验证。
