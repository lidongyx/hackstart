# 技能与插件的使用流程

## 安装前先问三个问题

1. 这项能力是否真的能减少重复劳动？
2. 它需要读取哪些文件、账号或外部服务？
3. 如果它失效，是否有手动替代方案？

## 使用技能的标准流程

```text
1. 查看技能说明和触发条件。
2. 用一个低风险样例试跑。
3. 让 Codex 说明它实际采用了哪套技能或步骤。
4. 检查输出和验证方式。
5. 稳定后再接入真实项目。
```

例如：

```text
$playwright
请打开 http://127.0.0.1:3007/docs/，检查首页、侧边栏和移动端布局。
只读和截图，不提交表单，不修改页面。
```

## 使用插件的标准流程

- 先确认插件来源和展示名对应的真实标识。
- 安装后重新打开线程，确认能力已经加载。
- 外部 App 另行完成授权，并检查授权范围。
- 先使用只读工具，再逐步开放写操作。
- 更新插件后重新跑一个固定样例。

## 插件不可用时的排查顺序

```text
查看是否安装 -> 查看是否启用 -> 检查授权 -> 检查工具白名单
-> 重启或新开线程 -> 用最小案例验证 -> 再考虑重装
```

不要把“没有返回结果”直接判断成插件失效；也可能是权限、账号、网络、路径或输入范围不对。

## 课后任务

选择一个只读技能，使用一份无敏感信息的样例跑通一次，并记录：触发方式、输入、输出、验证步骤和失败时的替代方案。
