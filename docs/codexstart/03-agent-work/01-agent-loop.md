# Agent 是怎样工作的

## 从聊天到执行

普通问答通常是“输入问题，得到答案”。Agent 任务更像一个循环：

```text
观察上下文 -> 规划步骤 -> 调用工具 -> 检查结果 -> 修正计划 -> 继续或交付
```

这意味着你不能只评价它的第一句回答，还要关注它是否在每一轮都用新的证据更新判断。

## 一次小型 Agent 任务

```text
请检查当前网页项目的首页是否能正常打开。
先观察项目结构和启动命令，再决定是否需要启动开发服务器。
启动后用浏览器检查首页标题、主要按钮、移动端布局和控制台错误。
如果发现问题，先列出问题和最小修复方案，得到我确认后再修改。
```

这里把任务拆成了观察、启动、浏览器检查、报告和修改确认五个阶段。Agent 仍然可以自主推进，但关键写入点不会被隐藏。

## 三种检查点

- **信息检查点**：你确认它理解了现状。
- **计划检查点**：你确认它准备做的事情在范围内。
- **结果检查点**：你确认它的证据足以交付。

任务越长，检查点越重要。不要让一个线程从“读取资料”一路自动走到“生产发布”。

## 课后任务

把一个大目标拆成至少 5 个 Agent 步骤，并给其中两个步骤加上“必须暂停等待确认”的条件。
