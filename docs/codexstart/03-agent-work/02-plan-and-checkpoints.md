# 长任务的计划与检查点

## 先定义阶段产物

一个好的阶段不是“做了很多事”，而是交付一个能检查的产物。例如做个人工作台时：

| 阶段 | 产物 | 检查方式 |
| --- | --- | --- |
| 研究 | 需求清单和信息架构 | 人工确认范围 |
| 设计 | 页面草图和数据字段 | 打开 HTML 预览 |
| 实现 | 可运行的最小版本 | 浏览器操作 |
| 加固 | 错误处理和空状态 | 边界测试 |
| 交付 | 使用说明和变更清单 | 按清单复核 |

## 长任务提示词

```text
这是一个多阶段任务。请维护一个简短的进度表：
- 已完成；
- 当前阶段；
- 下一步；
- 阻塞项；
- 需要我确认的决定。

每完成一个阶段先停下来汇报，不要自动跳过检查点。
如果发现原计划不合理，解释原因并提出新计划。
```

## 避免两个极端

- 计划过粗：只有“开始、完成”，中间无法定位问题。
- 计划过细：每个点击都写成一条，反而失去自主执行空间。

通常按“一个阶段对应一个可验证产物”来拆，最容易平衡控制和效率。

## 课后任务

选择“制作一份月度报告”或“搭建一个小网站”，写出 5 个阶段产物。每个产物必须能用文件、截图、命令输出或人工操作验证。
