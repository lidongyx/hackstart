# 用对话调试，而不是反复重试

## 把错误变成证据

遇到问题时，不要只说“还是不行”。一次有效的调试请求至少包含：

- 期望行为。
- 实际行为。
- 复现步骤。
- 错误信息或截图。
- 最近一次改动。
- 已经尝试过什么。

## 调试模板

```text
问题：点击“保存”后页面没有新增记录。
期望：记录出现在列表中，刷新后仍然存在。
复现：打开 index.html -> 填写标题 -> 点击保存。
证据：浏览器控制台显示 ______。
最近改动：刚把数据字段从 name 改成 title。
请先定位根因，解释证据如何支持你的判断；确认后再修改。
修改后增加一个能防止回归的最小检查。
```

## 让 Codex 逐步收敛

1. 先复现问题。
2. 缩小到最小案例。
3. 列出 2 到 3 个候选原因。
4. 用日志、测试或文件内容排除猜测。
5. 只做一个最小修复。
6. 重跑原问题和相关回归测试。

如果 Codex 连续两次修改仍没有证据，暂停继续改，要求它输出当前假设、已排除原因和下一条最有价值的检查。

## 课后任务

找一个过去解决得很慢的小问题，按“期望、实际、复现、证据、改动、验证”六项重写。比较两次提问的结果差异。
