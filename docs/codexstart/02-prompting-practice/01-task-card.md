# 写好一张 Codex 任务卡

## 为什么要用任务卡

“帮我把这个做好”对人类同事都不够清楚，对 Agent 更不够清楚。任务卡不是复杂的 Prompt 模板，而是帮你补齐关键信息的检查表。

## 六个字段

```text
任务名称：
目标结果：
已有输入：
允许范围：
完成标准：
必须确认的动作：
```

### 示例：整理下载目录

```text
任务名称：整理下载目录中的 PDF
目标结果：按年份和主题归档，并生成一份索引表。
已有输入：~/Downloads 中的 PDF；文件名可能混乱。
允许范围：只读取和移动 PDF；先输出计划，不删除文件。
完成标准：每个文件都有去向，索引表能打开，重复文件单独列出。
必须确认的动作：任何删除、覆盖或跨磁盘移动都要先暂停。
```

## 把“风格”写成可检查的规则

不要只说“做得高级一点”。把风格翻译成可观察的约束：

- 页面主操作只有一个。
- 表格列按重要性排序。
- 错误信息靠近出错字段。
- 手机宽度不能出现横向滚动。
- 颜色要有对比度，状态不能只靠颜色区分。

这类规则比形容词更容易执行，也更容易验收。

## 练习

把下面的需求改写成任务卡：

> 我想做一个小网站，帮我记录每天学了什么，看起来简洁一点。

最低要求是补充：数据字段、保存位置、页面操作、完成条件和不能做的事情。
