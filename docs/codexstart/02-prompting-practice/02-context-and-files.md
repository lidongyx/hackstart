# 上下文工程：让 Codex 看到该看的东西

## 上下文不是越多越好

把整个硬盘、整个仓库、十几张截图全部塞给 Codex，通常会降低判断质量。有效上下文有三个特点：**相关、最新、可定位**。

## 四层上下文

1. **项目层**：仓库用途、技术栈、启动命令、禁止事项。
2. **任务层**：这次目标、范围、验收标准。
3. **资料层**：具体文件、截图、数据和链接。
4. **历史层**：之前的决定、失败尝试和不能重复的问题。

如果一个信息会长期有效，放在项目说明或 `AGENTS.md`；如果只对这次任务有效，放在 Prompt；如果内容很长，放到独立参考文件并指出路径。

## 让 Codex 先做上下文盘点

```text
开始前请不要修改文件。
请输出：
- 你读取了哪些文件；
- 哪些文件与你的任务直接相关；
- 哪些信息可能已经过期；
- 你还缺什么上下文；
- 你准备修改哪些文件。
如果存在两个可能的入口，请先说明差异，不要自行猜一个。
```

## 常见错误

- 只给截图，不给实际文件路径。
- 只说“最新版”，不提供版本号或日期。
- 让 Codex 参考一个已经废弃的组件。
- 把秘密配置和普通配置混在一个文档里。
- 一次给出互相矛盾的多个规则。

## 课后任务

选一个你正在维护的目录，写一份一页纸的“项目上下文卡”：用途、入口、命令、关键目录、验证方式和禁止事项。下一次任务直接引用这张卡。
