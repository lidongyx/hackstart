# 权限、安全与人工确认

## 先分清三种动作

让 Codex 工作时，可以把动作分成三类：

1. **读取**：查看文件、日志、网页和配置。
2. **准备**：生成计划、草稿、补丁、预览环境和测试报告。
3. **写入或产生外部影响**：改文件、发消息、提交代码、部署、删除、付款。

默认应当让前两类尽量自动化，第三类保留人工确认。尤其是不可逆动作，不要用一句“全部自动完成”带过。

## 一个安全的执行模板

```text
请按以下安全流程执行：
1. 先读取并说明会涉及哪些文件和外部系统；
2. 给出计划、风险和回滚方式；
3. 只执行低风险的准备动作；
4. 遇到发送、删除、付款、部署、权限或线上配置时暂停并等待我的明确确认；
5. 完成后列出实际改动、验证结果和剩余风险。
```

## 40 条实用注意事项

下面的清单可以作为每次任务开始前的快速检查。不是每条都必须机械执行，但高风险任务至少要覆盖相关项目。

### 任务边界

1. 先说结果，再说过程。
2. 给出允许修改的目录或文件。
3. 明确哪些文件禁止修改。
4. 说明是否允许新增依赖。
5. 说明是否允许联网。
6. 说明是否允许使用外部账号。
7. 把一次性目标和长期规则分开。
8. 把“看一下”改成可验收的动作。
9. 复杂任务先拆阶段。
10. 不要让 Codex 猜测关键业务规则。

### 上下文与资料

11. 先让 Codex 列出它已经看到的资料。
12. 提供真实的文件路径，不要只描述文件名。
13. 重要规则写进项目说明，而不是每次临时重复。
14. 资料有版本时标明日期和来源。
15. 私密数据优先脱敏后再提供。
16. 不要把 API key、密码和 cookie 粘进 Prompt。
17. 让 Codex 区分事实、假设和待确认事项。
18. 对外部网页内容保持来源意识。
19. 让 Codex 在不确定时停下来问。
20. 不要用一份过期截图代表当前系统状态。

### 执行与修改

21. 修改前先查看现状。
22. 小步修改，减少一次改动的范围。
23. 让每一阶段都有可运行状态。
24. 重要变更前保留 Git diff 或备份。
25. 不要让 Codex 静默覆盖用户已有改动。
26. 删除动作先列出对象和数量。
27. 批量操作先用少量样本演练。
28. 线上动作先做 preview 或 dry-run。
29. 生产环境和测试环境分开确认。
30. 不要把“命令成功返回”当作业务成功。

### 验证与交付

31. 验证命令写进任务要求。
32. 要求报告实际执行了什么，而不是计划做什么。
33. 同时检查正常路径和失败路径。
34. UI 任务要检查桌面、移动端和空状态。
35. 数据任务要检查数量、格式和边界值。
36. 文件任务要检查输出位置和命名。
37. 让 Codex 给出未覆盖风险。
38. 重要结果由人抽样复核。
39. 交付物和中间文件分目录保存。
40. 把重复出现的流程沉淀成 Skill 或脚本。

## 课后任务

从清单里选 5 条，加入你自己的项目 `AGENTS.md` 或工作说明中。注意：不要把只对某一次任务有效的要求写成长期规则。
