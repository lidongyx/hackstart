# 完成你的第一个 Codex 任务

## 练习目标

我们做一个“个人阅读清单”，只使用三个静态文件：

```text
reading-list/
  index.html
  styles.css
  app.js
```

它不连接真实账号、不发送数据、不涉及付款，适合第一次练习。

## 第一步：先让 Codex 规划

```text
我想在当前空目录创建一个个人阅读清单网页。
要求：
- 使用原生 HTML、CSS、JavaScript，不使用框架和构建工具；
- 可以添加书名、作者和阅读状态；
- 可以按“全部、未开始、阅读中、已完成”筛选；
- 使用 localStorage 保存数据；
- 手机宽度下也能正常使用。

现在只做两件事：
1. 先列出实现计划和文件职责；
2. 列出你认为需要我确认的取舍。
不要创建文件。
```

好的结果应该包含文件职责、数据结构、交互状态和验证方式，而不是直接贴一大段代码。

## 第二步：让它分阶段实现

```text
按刚才的计划执行第一阶段：只创建基础页面结构和样式。
不要实现数据逻辑，不要添加依赖。
完成后告诉我改了哪些文件、如何手动验证，以及下一阶段建议。
```

然后再执行第二阶段：

```text
继续第二阶段：实现添加、筛选、状态切换和 localStorage。
先阅读现有文件，保持现有视觉结构，不要重写无关部分。
完成后运行语法检查或用浏览器做一次最小交互验证。
```

## 第三步：要求它证明完成

```text
请做一次交付前检查：
- 打开 index.html，验证能新增一条阅读记录；
- 验证筛选按钮能切换；
- 刷新后数据仍在；
- 检查移动端是否出现横向滚动；
- 列出未覆盖的风险。
不要为了让检查通过而隐藏错误。
```

## 你应该观察什么

- Codex 是否在修改前读了已有文件。
- 每次修改是否只触及约定范围。
- 它是否说明了验证动作，而不是只说“已经完成”。
- 发现失败时，它是否先定位原因再修复。
- 它是否保留了你可以人工检查的中间结果。

## 验收清单

- [ ] 三个文件都在预期目录。
- [ ] 可以新增一条记录。
- [ ] 可以改变阅读状态。
- [ ] 筛选结果和计数一致。
- [ ] 刷新页面后记录仍然存在。
- [ ] 没有引入不必要的依赖。

## 课后任务

把阅读清单改成“课程任务清单”，增加截止日期和优先级。先让 Codex 输出数据结构和改动计划，再允许它修改文件。
